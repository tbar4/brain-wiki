# It is more common to pass closures to threads
It is more common to pass closures to thread which allows us to safely capture values and move them into the new thread. We need to use the `move` keyword to move ownership of the value `numbers` into the thread. If we didn't do this, there is a chance that the thread outlives the value of `numbers`. Since a thread may run to the very end of the program's execution, the `spawn` function has a `'static` lifetime bound on its argument type, meaning it only accepts functions that may be kept around forever[^1].

```rust
use std::thread;

fn main() {
	let numbers = vec![1, 2, 3];
	
	// Ownership of numbers is moved into
	// the new thread.
	thread::spawn(move || {
		for n in &numbers {
			println!("{n}");
		}
	}).join().unwrap();
}
```

To get a value back out from a thread you return it from the closure.

```rust
use std::thread;

fn main() {
	let numbers = Vec::from_iter(0..=1000);
	
	let t = thread::spawn(move || {
		let len = numbers.len();
		let sum = numbers.iter().sum::<usize>();
		sum / len
	});
	
	let average = t.join().unwrap();
	
	println!("Average: {average}");
}
```
